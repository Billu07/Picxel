# Contributing to Picxel

Thanks for helping. This guide takes you from clone to merged pull request.

## Ground rules
- **The detector test.** Picxel never helps hide where an image came from. If a change works better when an AI detector, watermark, or disclosure label *fails*, it's out of scope, and the PR will be closed. Background: [D-001](decision.md#d-001--pivot-no-detector-evasion--inspector--studio).
- Be kind. The [Code of Conduct](CODE_OF_CONDUCT.md) applies everywhere.
- Never report security issues in public. Follow [SECURITY.md](SECURITY.md).
- Never attach private images to issues. Describe the image, or use a public test image.

## Set up
1. Install [uv](https://docs.astral.sh/uv/getting-started/installation/).
2. `uv sync`
3. `uv run pre-commit install`
4. `uv run picxel dev`, then open http://127.0.0.1:8000

The app runs without a database in Phase 0. To work with PostgreSQL:

```bash
docker compose up db      # also creates a picxel_test database
cp .env.example .env      # then uncomment PICXEL_DATABASE_URL and PICXEL_TEST_DATABASE_URL
uv run picxel migrate
```

## Workflow
1. Branch from `main`: `feat/…`, `fix/…`, `docs/…`, `chore/…`.
2. Commit using [Conventional Commits](https://www.conventionalcommits.org/) and sign off ([DCO](https://developercertificate.org/)):
   `git commit -s -m "feat(studio): add Pinterest pin preset"`
3. Run `uv run picxel check` before pushing.
4. Open a pull request. CI must be green and a maintainer must review it. PRs are squash-merged.

## Definition of Done
- [ ] `uv run picxel check` passes: ruff, mypy (strict), import contracts, tests, coverage ≥ 80%
- [ ] Tests added or updated
- [ ] Passes the detector test
- [ ] User-facing copy talks about *signals*, never accusations
- [ ] Accessibility considered (keyboard, contrast, labels)
- [ ] Docs updated. If the change deviates from `project.md`, add a `decision.md` entry first.

## Architecture boundaries
`uv run lint-imports` enforces these:
- `app.studio` must never import `app.inspector`.
- Layers, top to bottom: `cli` → `main` → `factory` → `errors` → `api | web` → `inspector | studio` → `imaging | db` → `core`. A module may import only from layers below it.

## Database migrations
Use sequential four-digit revision IDs:

```bash
uv run alembic revision --autogenerate --rev-id 0002 -m "add analyses table"
uv run picxel migrate
```

Review every autogenerated migration by hand. Never store image bytes or personal metadata (`project.md` §10).

## Good first contributions
Watch for issues labeled `good first issue`. Once presets exist (Phase 3), verifying a platform preset against official documentation is the easiest way in.
